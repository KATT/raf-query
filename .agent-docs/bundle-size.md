# Bundle size

`pnpm bundle-size` (`tooling/bundle-size`, CI job "Bundle Size") bundles small entries that each import one slice of raf-query, and prints each one's gzip size and the opt-in features found in it. React is external. The run fails when a bundle holds an opt-in feature its entry doesn't import, lacks one it does, or when the base entry passes 5 kB gzip ([decisions/bundle-budget.md](./decisions/bundle-budget.md)).

Every opt-in feature is absent from the bundles that don't import it (the run fails otherwise). Markers:

- **TanStack defaults.** The features TanStack Query runs without being asked (retries, refetch on focus and reconnect, `refetchInterval`, hydration) cost 1.03 kB gzip together, 23% over the base. Each alone: hydration 0.41, `retry()` 0.29, `polling()` 0.22, `focusRefetch()` 0.15, `reconnectRefetch()` 0.12 kB; they sum to 1.19 kB because they share the feature plumbing and stale-read helpers. Structural sharing, gc and refetching stale data on read are in the base.
- **Markers.** A feature counts as present when its module has code in the bundle (`core/hydration`, `core/infinite`, `boundary/index`, `react/use-query`) or, for features sharing a module, when a string that survives minification is in the output: `"[object Response]"` (`retry()`), `"refetchInterval"` (`polling()`), `"visibilitychange"` (`focusRefetch()`), `"refetchOnReconnect"` (`reconnectRefetch()`), `".tags"` (tags, whose module `core/groups` also holds the `groups()` feature).
- **Streams aren't opt-in.** Folding an async iterable into the data lives in the entry (`entry.ts`), so every bundle carries it; a stream query costs only its own options.
- **Groups are in the base fixtures.** The fixtures build their keys with `group()`, the recommended way, so their bundles carry it: 152 B gzip on its own in production (esbuild, `NODE_ENV=production`), 62 B next to core, which shares its helpers. It sits in `core/keys` on the main entry and tree-shakes away in an app that writes its keys by hand: the base with a hand-written key is 4.42 kB (4525 B against 4575 B), with no `group()` code in it. Its development check that a subgroup and a query don't share a name is behind `process.env.NODE_ENV !== "production"` and costs 0 B in production. Matching a group as a key prefix keeps core 48 B under matching object groups.
- **Binding the builders is free.** `bindQueryOptions` and `bindUseQueryClient` return the plain functions, typed for a root ([decisions/bound-builders.md](./decisions/bound-builders.md)). The bound fixture (`bound.tsx`) is 4612 B gzip; the same app with the plain builders is 4590 B, so the two binders cost 22 B (64 B minified). Neither pulls in `core/infinite`: only `bindInfiniteQueryOptions` does, in apps that page. Typing `queryOptions` as a `const` of `QueryOptionsBuilder` moved the base from 4575 to 4579 B gzip (its minified output is 12 B smaller).
- **Paging is opt-in.** `useInfiniteQuery` is the only reader of `core/infinite` (page params, `pagesAround`), so `useQuery` apps don't ship it ([decisions/split-infinite-hook.md](./decisions/split-infinite-hook.md)). Splitting the hooks took the base from 4.30 to 4.15 kB.
- **Tracked state is in the base.** The read-field tracking both hooks share (`react/tracked`) costs 0.31 kB: the base went from 4.15 to 4.46 kB ([decisions/tracked-state.md](./decisions/tracked-state.md)). Keeping own `"__proto__"` keys in structural sharing added 0.01 kB ([decisions/structural-sharing.md](./decisions/structural-sharing.md)).
- **Target lists cost the `…Many` verbs about 0.04 kB.** Taking a list of targets in `invalidateMany`, `resetMany` and `removeMany` (one stamp per target, each entry checked against all of them) took the tags entry from 4.82 to 4.86 kB and everything from 6.93 to 6.98 kB. The base imports no `…Many` verb.
- **`recommended()` holds retry, focus and reconnect refetch, and polling.** Dropping the action feature from it took everything from 6.98 to 6.91 kB; the other entries moved by at most 0.01 kB.
- **The base sits at 4.47 kB of 5 kB.** Anything added to the always-imported path (`createQueryClient`, `load`, `useQuery`, the entry) has to pay for itself or go behind a link, feature or subpath.

## What defeats tree-shaking

- **Anything reachable from the always-imported path.** Behaviors that every client runs can't be shaken, so retries, focus/reconnect, polling, hydration, tags and paging are opt-in: links, features, subpaths, or a `~run` function set only by `infiniteQueryOptions`.
- **`export * as X` in a library build.** Rolldown/tsdown compile it to an `__exportAll` getter object, which keeps every member in `dist/`. The packages export named members only. Check with `pnpm bundle-size --dist` after `pnpm build`.
- **Runtime branches on build-time facts.** `if (router.isServer) setupServer()` keeps the server half's imports; use an export condition ([decisions/router-browser-build.md](./decisions/router-browser-build.md)).
- Dynamic access (`X[key]`) and re-exported `export *` of a module with side effects keep everything.
