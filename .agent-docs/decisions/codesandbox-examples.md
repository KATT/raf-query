# Examples on CodeSandbox from a generated branch (human asked, agent designed)

- Human: abandon StackBlitz and its WebContainers workarounds, run the examples on CodeSandbox instead, and keep the per-example pnpm workspace layout the StackBlitz copies had.
- CodeSandbox runs a real Linux VM, so the copies run the apps' own scripts: `vp` (native) and Turbopack. Nothing WebContainers-specific is needed: no AsyncLocalStorage preload, no `next dev --webpack`, no serialized requests, no core workaround for its `Promise.resolve`.
- CodeSandbox "Repositories" (`/p/github/...`) take no new imports since 2026-04-01. What's left is a synced template (`/p/devbox/github/<owner>/<repo>/tree/<branch>/<folder>`), which opens one folder. A folder of `main` can't reach `examples/.shared/`, so `tooling/codesandbox` writes standalone copies, and `.github/workflows/codesandbox.yaml` pushes them to the `codesandbox` branch after each Release (the copies install the just-published `@raf-query/*`). Synced templates need no sign-in, and branch names with `/` work in the URL.
- Each copy: `apps/<app>` + `packages/{db,ui}`; the monorepo's `pnpm-workspace.yaml` with the copy's packages (keeps the `vite` → Vite+ override), plus `@raf-query/*` in `minimumReleaseAgeExclude` (pnpm 12 otherwise rewrites the file to exempt a just-published version); the monorepo's `packageManager` and `engines` on the root `package.json`; `.devcontainer/devcontainer.json` on `ghcr.io/codesandbox/devcontainers/typescript-node:24`; `.codesandbox/tasks.json` (`pnpm install`, then `pnpm dev` with `preview.port` from the dev script's `--port`); `.codesandbox/template.json` (title from the README, description from `package.json`).
- That image's Node 24.10 bundles corepack 0.34, which can't start pnpm 12 (`Cannot find module …/bin/pnpm.cjs`). Its global pnpm 10.18 switches itself to the `packageManager` version, so plain `pnpm install` is enough; no corepack setup task.
- Preview URLs are `https://<id>-<port>.csb.app`. Vite rejects that `Host` (403) and Next 16 blocks `/_next/*` dev requests, including the HMR websocket, from that `Origin`. So `examples/tanstack-start/vite.config.ts` sets `server.allowedHosts: [".csb.app"]` and `examples/nextjs/next.config.ts` sets `allowedDevOrigins: ["*.csb.app"]`, in the source apps, so the copies stay unpatched.
- Lost: opening the whole monorepo from `main` (one link for both apps, both dev servers on one VM, a full workspace install), and keeping StackBlitz alongside.
