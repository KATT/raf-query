# Tracked state (human decided)

- Alex (2026-11-08): "we should have a stable reference depending on what you use in the results - if e.g. controls.isFetching isn't read we shouldn't update the results when it changes. tanstack query has this and it reduces the amounts of renders".
- What: `useQuery` and `useInfiniteQuery` return their state as a `Proxy` that records each field read (`packages/react/src/tracked.ts`). A write re-renders the component only when the source thenable (before `select` / `result`) changed identity or status, or a recorded field changed (`Object.is`). The state object keeps its identity until a recorded field changes; functions (`refetch`, `fetchNextPage`, `fetchPreviousPage`) are stable wrappers that call the latest render's.
- Reused from TanStack Query (`.repos/query/packages/query-core/src/queryObserver.ts`): `#trackedProps` (line 85), `trackResult` wrapping the result in a `Proxy` whose `get` calls `trackProp` (331–352), and `shouldNotifyListeners` notifying only when an included prop changed by `!==` (753–785). `react-query/src/useBaseQuery.ts:138` tracks by default, as we always do. The tracked set only grows, like theirs.
- Differs from TanStack: with nothing read they notify on any change; we still re-render on a thenable change, because the data lives in the thenable, not in the state. There's no `notifyOnChangeProps` option.
- Compiler safety: the tracker lives in `useState` and only the functions in `tracked.ts` change it. `readQuery` takes both entries' states as arguments, so a memoized call recomputes on every write. The subscribe callback filters notifications with `renderedChanged`, which re-reads `current.state` / `shown.state` through the last render's `refresh`; `getSnapshot` is still `current.state`.
- Caveats: a field read only outside render (effects, handlers) isn't tracked and holds the last render's value. A discarded concurrent render can leave a baseline that was never committed; the next write compares against it (TanStack has the same).
- Tests: the compiler suite's two tracked tests (no render on an untracked refetch, renders on a tracked one, a field first read after a re-render is tracked; the paged one for `useInfiniteQuery`), `use-query.test.tsx` "tracked state" (state and function identity, a no-field reader re-renders when its thenable settles), `use-infinite-query.test.tsx` (stable `fetchNextPage`). Core's `read` / `readPages` helpers spread the state so every field is read in render.
- Cost: 0.31 kB gzip on every bundle with the hooks (base 4.15 → 4.46 kB).
