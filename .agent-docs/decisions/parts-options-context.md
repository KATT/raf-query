# Plugins declare top-level options and `queryFn` context (human, 2026-11-11)

- Why (human): a free-form `meta` bag is loose in two places. A builder that takes any field lets a typo, or an option of a plugin the client lacks, compile and do nothing. And a library can't name the app's client, so its factories go unchecked unless it can bind to something else.
- **One function makes a plugin**: `plugin<Decl>({ link?, setup?, context? })`. `Decl` is an interface, `{ readonly options?: …; readonly context?: … }`. A `link` wraps every request, a `setup` is a feature that runs while a provider has the client mounted, and a `context` object is merged into every `queryFn`'s context. `plugin<Decl>()` without a definition only declares options (an app's `owner`, tags). A plugin that declares a `context` must give it, for the client or per request from its link ([link-context.md](./link-context.md)). The name is "plugin" ([plugins-and-bound-builders.md](./plugins-and-bound-builders.md)).
- **One `plugins` array** on `createQueryClient`; links run outermost first in array order. `recommended()` returns an array of plugins.
- **Options are top-level query options**: `queryOptions({ queryKey, queryFn, retry: 1 })`. Links read `op.options`, `where` targets read `query.options` (`QueryInfo<TOptions>`, `Target<TOptions, TParam>`).
- **Every builder is bound** ([plugins-and-bound-builders.md](./plugins-and-bound-builders.md)): the packages export no `queryOptions`. An app binds per client, `bindQueryOptions<typeof makeQueryClient>()` in its `raf.ts` ([bound-builders.md](./bound-builders.md)). No global `Register`: several clients per program must work, and the human does not want global pollution.
- **`bindQueryOptions()` without a type argument** takes the core's options only (`CoreOptions`: `staleTime`, `gcTime`, `structuralSharing`, `ssr`), its `queryFn` gets `client`, `queryKey` and `signal`, and its factories run on every client. It is what a package with no requirements uses.
- **A client runs a factory when it has at least the plugins the factory's builder is bound to.** Roots compare structurally, so `QueryClient<Root<A & B>>` is assignable to `QueryClient<Root<A>>`. A root has every declared option present and possibly `undefined` (`Present`); with optional fields, a root without a plugin would be assignable to one with it. `Present`, `Plain` and `Root` are conditional types (`T extends unknown ? { … } : never`): as aliases of mapped types, TypeScript compares `Root<A>` with `Root<A & B>` by a variance it measures wrong, and accepts a client with fewer plugins.
- The bare `QueryClient` is `QueryClient<NoPlugins>`: any client. Verbs given one take only the factories and targets that need no plugin. `load` checks each entry's factory against the client too. So whatever carries an app's client is typed `ReturnType<typeof makeQueryClient>` (a router's context, a React Router context), and components get it from the bound `useQueryClient`. `ClientFor<typeof factory>` names a client that runs a factory.
- **Libraries bind to plugin declarations**: `bindQueryOptions<Convex & Optional<Retry>>()`. The factories need the `Convex` plugin; `Optional<Retry>` lets them set `retry`, which takes effect on clients with `retry()`, without needing it (`RootOf` is what the factories need, `SetsOf` what they can set). `Retry`, `Polling`, `FocusRefetch` and `ReconnectRefetch` are exported for this, and an app uses them to bind a builder to the plugins several of its clients share.
- **`defaults` holds every option's client-wide default**: `createQueryClient({ plugins, defaults: { staleTime: 30_000, retry: 1 } })`, typed by the plugins of the same call. A link's `op.options` is the query's options over the defaults; features read an option with `optionOf` (`features/shared.ts`).
- **`staleTime` stays a core option**, not a plugin's, because `load` reads it.
- `OptionsOf<T>` types a fragment of options several factories spread.
- Lost: `meta` as a free-form bag, and `context.meta`; `link()` and `feature()` (and the `Link`, `Feature` and `QueryMeta` types); the bare `QueryClient` taking any bound factory; a global `Register`; naming the client in each factory with `satisfies` or a `client:` phantom.
- Where: `packages/core/src/root.ts`, `client.ts` (`plugin`, `createQueryClient`), `options.ts`, `infinite/infinite.ts`, `verbs.ts`, `load.ts`, `keys/targets.ts`, `presets.ts`; `packages/react/src/bind.ts`.
- Tests: `packages/core/src/types.test-d.ts` ("root types"), `extension.test-d.ts`, `client.test.ts` ("a client's plugins"), `keys/tags-recipe.test.ts`; `packages/react/src/hooks.test-d.tsx` ("bindUseQueryClient").
- Docs: `www/content/plugins.md` (its `#writing-a-plugin`, `#typing-options-by-the-client` and `#binding-a-library-to-plugins` anchors are in the packages' `@see` links, which `workspace/require-docs-link` checks); samples `www/samples/tanstack-start/src/docs/plugins*.ts(x)` and each sample app's `raf.ts`.
- (agent, after an independent review) Roots agree on an option only when its type is the same in both: `Root` carries a phantom `"~options"` with each option as a function of its own type. Compared covariantly, a factory built for `owner?: string` ran on a client whose plugin reads `owner?: "a" | "b"`. The set of options stays open, so a client with more plugins still runs the factory. Not covered: a library's `Optional<…>` option is not compared with what the client declares for the same name.
- (agent, after an independent review) A query's option that is `undefined` takes the client's default everywhere: links get the options through `withDefaults` (`entry.ts`), which skips `undefined`, as the core and the features already did.
