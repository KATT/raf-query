# Parts declare top-level options and `queryFn` context (human, 2026-11-11)

- Why (human): a free-form `meta` bag is loose in two places. An unbound builder takes any field, so a typo, or an option of a part the client lacks, compiles and does nothing. And a library can't name the app's client, so it can't bind its builders and its factories go unchecked.
- **One function makes a part**: `part<Decl>({ link?, setup?, context? })`. `Decl` is an interface, `{ readonly options?: …; readonly context?: … }`. A `link` wraps every request, a `setup` is a feature that runs while a provider has the client mounted, and a `context` object is merged into every `queryFn`'s context and `client.context`. `part<Decl>()` without a definition only declares options (an app's `owner`, tags). A part that declares a `context` must give it.
- **One `parts` array** on `createQueryClient`; links run outermost first in array order. `recommended()` returns an array of parts.
- **Options are top-level query options**: `queryOptions({ queryKey, queryFn, retry: 1 })`. Links read `op.options`, `where` targets read `query.options` (`QueryInfo<TOptions>`, `Target<TOptions, TParam>`).
- **Unbound builders take the core's options only** (`CoreOptions`: `staleTime`, `gcTime`, `structuralSharing`, `ssr`), their `queryFn` gets `client`, `queryKey` and `signal`, and their factories run on every client.
- **Binding stays per client**: `bindQueryOptions<typeof makeQueryClient>()` in the app's `raf.ts` ([bound-builders.md](./bound-builders.md)). No global `Register`: several clients per program must work, and the human does not want global pollution.
- **A client runs a factory when it has at least the parts the factory's builder is bound to.** Roots compare structurally, so `QueryClient<Root<A & B>>` is assignable to `QueryClient<Root<A>>`. A root has every declared option present and possibly `undefined` (`Present`); with optional fields, a root without a part would be assignable to one with it. `Present`, `Plain` and `Root` are conditional types (`T extends unknown ? { … } : never`): as aliases of mapped types, TypeScript compares `Root<A>` with `Root<A & B>` by a variance it measures wrong, and accepts a client with fewer parts.
- The bare `QueryClient` is `QueryClient<NoParts>`: any client. Verbs given one take only the factories and targets that need no part. `load` checks each entry's factory against the client too. `ClientFor<typeof factory>` names a client that runs a factory.
- **Libraries bind to part declarations**: `bindQueryOptions<Convex & Optional<Retry>>()`. The factories need the `Convex` part; `Optional<Retry>` lets them set `retry`, which takes effect on clients with `retry()`, without needing it (`RootOf` is what the factories need, `SetsOf` what they can set). `Retry`, `Polling`, `FocusRefetch` and `ReconnectRefetch` are exported for this, and an app uses them to bind a builder to the parts several of its clients share.
- **`defaults` holds every option's client-wide default**: `createQueryClient({ parts, defaults: { staleTime: 30_000, retry: 1 } })`, typed by the parts of the same call. A link's `op.options` is the query's options over the defaults; features read an option with `optionOf` (`features/shared.ts`).
- **`staleTime` stays a core option**, not a part's, because `load` reads it.
- `OptionsOf<T>` types a fragment of options several factories spread.
- Lost: `meta` as a free-form bag, and `context.meta`; `link()` and `feature()` (and the `Link`, `Feature` and `QueryMeta` types); the bare `QueryClient` taking any bound factory; a global `Register`; naming the client in each factory with `satisfies` or a `client:` phantom.
