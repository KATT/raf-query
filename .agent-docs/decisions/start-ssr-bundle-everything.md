# The Start app bundles every dependency into the server build (agent)

- `examples/tanstack-start` sets `ssr.noExternal: true` for `build` in `vite.config.ts`. Dev keeps Vite's default, so `vp dev` loads dependencies from `node_modules`.
- Why: without it, every request to the Start app on Vercel returns 500 `{"message":"HTTPError"}` while the Vercel checks stay green. The log says `Cannot find module 'react'` from `_ssr/router-*.mjs`. Base UI (#125) is the dependency that triggers it.
- Mechanism: the build runs twice. Vite's SSR build keeps a dependency external when it resolves from the app's root (`react`) and inlines it when it doesn't (pnpm: `@base-ui/react` comes through `@examples/ui`, and its CommonJS dependency `use-sync-external-store`). Inlined CommonJS that `require`s an external becomes `createRequire(import.meta.url)("react")`. Nitro's second bundle can't follow that, and the Vercel function ships without `node_modules`. Locally `node_modules` is there, so `pnpm start` works.
- To check a build the way Vercel runs it: `VERCEL=1 pnpm build`, copy `.vercel/output/functions/__server.func` outside the repo, `import` its `index.mjs`, and call `default.fetch(new Request(...))`. `rg '__require\("'` on the copy should list only Node built-ins.
- Lost: adding `@base-ui/react` / `use-sync-external-store` as direct app dependencies (fixes this package only; the next transitive CommonJS dependency breaks it the same way); `ssr.external` for the shim (Nitro can't resolve it from the app either); making `react` `noExternal` alone (two copies of React with `@tanstack/react-router`'s).
