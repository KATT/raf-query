# Behaviors are opt-in parts that declare their options (human decided)

- The kernel does nothing beyond caching. Each behavior is a **part** given to `createQueryClient({ parts })`. Retries and timeouts are parts with a link (`retry()`, `timeout()`), which wraps each request. Refetch on focus or reconnect and polling are parts with a `setup`, called features (`focusRefetch()`, `reconnectRefetch()`, `polling()`), which watch the client while a provider has it mounted. A part with neither only declares options, which is how an app writes tags ([tags-userland.md](./tags-userland.md)).
- `recommended()` is the preset the docs teach: an array with retry, focus and reconnect refetch, and polling. Pass it as `parts`, or spread it among an app's own. Which preset is the default (A/B/C) is open ([open-questions.md](../open-questions.md)).
- Per-query settings are top-level query options declared by the part that reads them (`part<Retry>({ link })`, `part<Polling>({ setup })`), so a query can only set `retry` or `refetchInterval` when its client has the part. How parts declare options and `queryFn` context, and how clients and factories are checked against each other, is in [parts-options-context.md](./parts-options-context.md); how an app binds its builders is in [bound-builders.md](./bound-builders.md).
- The split may be folded into the core later; apps that use `recommended()` shouldn't notice.
- Where: `packages/core/src/client.ts`, `links/<name>/`, `features/<name>/` (one folder per behavior, with its test; [core-behavior-folders.md](./core-behavior-folders.md)), `presets.ts`, `root.ts`.
