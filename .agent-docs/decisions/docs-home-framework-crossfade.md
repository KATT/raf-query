# Homepage framework switch cross-fades with `<ViewTransition>` (human asked)

- `FrameworkPanels` (`www/src/components/framework-panels.tsx`) wraps the hero code and the walkthrough panels in React's `<ViewTransition>`; switching mode plays its default cross-fade.
- **Defer the mode.** `Route.useSearch()` reads the router store through `useSyncExternalStore`, which React commits synchronously even inside the router's `startTransition`, and view transitions only run for transition-lane commits. `useDeferredValue(mode)` moves the switch into one. Lost: relying on the router's `startTransition` (fired a view transition only by accident).
- **React must mutate the boundary.** Visibility stays CSS on `html[data-framework-mode]` (no prerender flash), but React only animates boundaries whose DOM it changed. The wrapper renders `data-framework-panels={mode}` after hydration only (`useSyncExternalStore` server snapshot `false`), so a `?mode=` deep link doesn't add a hydration mismatch.
- **Flip `<html>` in the ref, not in render.** Render-time `syncFrameworkModeAttribute` changed the DOM before the old snapshot, so old and new were identical. Ref callbacks attach in React's layout phase, inside the `startViewTransition` update. (`useLayoutEffect` is lint-banned.)
- The overlay paints above the page, so the sticky header and the pill carry permanent CSS `view-transition-name`s to stay on top. `::view-transition-group(.framework-panels)` clips the taller outgoing panel; `prefers-reduced-motion` turns the animations off.
