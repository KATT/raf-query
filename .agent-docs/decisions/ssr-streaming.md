# SSR streaming in core (agent, human asked)

Human: "everything until the very edge where we expose apis for react should be effect native".

- **`QueryCache.dehydrateStream(cache, options)` (core) returns `{ initial, updates, close }`**: `updates` is a `ReadableStream` that `close()` ends after flushing the pending batch. Calling it snapshots and subscribes in one synchronous step, so no event falls between them. It's a record rather than one stream because the router needs `initial` synchronously, in its dehydrated state. The `/effect` `dehydrateStream(cache, options)` wraps it in `acquireRelease` with `updates` as a `Stream`; `hydrateStream(cache, stream)` is the receiving end.
- **Batches are handed over within the microtask**: changed entries collect for a microtask, then `controller.enqueue`, so a waiting reader gets them before React streams the boundaries those entries unblock. A core test reads the `ReadableStream` and checks it within three microtasks; an Effect `Stream` over it wakes a scheduler tick later, which is why the router integration uses core's stream directly.
- **"Each entry once" is the `sent` option** (`Set<string>` of hashes) on `DehydrateOptions`. `dehydrateStream` uses one internally. React keeps one set per client (`sent.ts`), shared by `HydrationBoundary` (skip what earlier boundaries sent), `Hydrate` (mark what the RSC payload carried) and `QueryProvider`'s SSR stream (skip both). It's in a module without `"use client"` because the RSC boundary calls it.
- **Redacted errors are `RedactedError`** (an `Error` subclass with `_tag`, `hash`, message `Query <hash> failed`). After serialization the browser sees a plain `Error` with those fields.
- Edges kept as they were: the router's client reads the `ReadableStream` with a reader loop and reports a failed read with `console.error` (no Effect in the browser bundle). Next's `RAF_QUERY_SSR` global stays a direct `hydrate` per pushed script: an inline script must hydrate before React hydrates the markup after it, and a stream would defer that to a later tick. `Hydrate`'s render-vs-commit split stays in React.
