# `enabled` is a boolean, as in TanStack (human asked, agent shaped)

- Human: "enabled might be nicer than ssr", then "the enabled flag can just be a boolean and described how tanstack does it". `enabled?: boolean` is a query option, default `true`. Browser-only queries use TanStack's idiom, `enabled: typeof window !== "undefined"`; the factory runs per call, so each side decides for itself.
- Why a flag at all (human asked whether apps like `kattcorp/isbabyoutyet` could do without it): a `queryFn` that returns a placeholder (`null`) on the server caches it, the server sends it, and the browser never replaces it, since nothing refetches on mount and first-load loaders run on the server. isbabyoutyet's push capability and visitor tag would read `null` until focus or invalidation. Not dehydrating disabled entries is what lets the browser run them.
- Where it's disabled, `fetchEntry` never runs the request. In a `load`, a fetch entry, or an ensure entry with no data, rejects with `QueryDisabledError`; a prefetch entry stays quiet. Invalidation and the refetch features skip it; `dehydrate` skips disabled entries.
- Readers: on a server client, the read rejects with `QueryDisabledError`. `useQuery` returns the rejected thenable, so a component that only passes it down still renders, and `use()` throws it. A streaming render can't wait for a later factory call, and a rejection that reaches `use()` makes React render the Suspense fallback there and retry in the browser. Tests: `use-query.test.tsx` ("on the server"). In the browser, the entry stays pending, so `use()` suspends instead of reaching the error boundary (the human worried `enabled` would fight Suspense; TanStack's `useSuspenseQuery` forces `enabled: true` for the same reason). A later render whose options enable it starts the request.
- Lost: `enabled: "browser"`, which would read the client's `isServer` instead of a global. TanStack users already write `typeof window`, and one boolean is less to learn.
- Unlike TanStack, a refetch doesn't run a disabled query: a server-disabled query can't run at all, and one rule is simpler.
- Not used: React's internal `react.recoverable` symbol (not exported in stable React).
- Tests: `entry.test.ts` ("doesn't run a disabled query"), `load.test.ts` ("rejects for a disabled query it has to wait for"), `use-query.test.tsx` ("leaves a disabled query pending in the browser", "throws for a disabled query").
