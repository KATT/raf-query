# Experiment: effect-query, typed error boundaries on an Effect-only cache (human asked, agent designed)

- Human: a raf-query-like library built only on Effect / Effect RPC, with type-safe error boundaries inspired by result-rpc (catch a generic error such as auth higher up, narrower ones further down), more Effect-native; competing options as separate PRs with interactive demos that show exhaustive errors, type errors for unhandled ones, and that a fully handled chain can't produce an error.
- Lives in `.experimental/effect-query/` (`package/`, `demo/` on port 3010). Effect's own `useAtomSuspense` throws `Cause.squash` to an untyped boundary, so there was nothing to reuse.

Agent decisions:

- **The cache keeps each query's `Exit`**, so a failure keeps its whole `Cause`. Routing reads it: `Cause.findError` finds a typed failure, which goes to the innermost boundary in the chain that lists its `_tag`, or back to the component. A cause without one (defects, interrupts) goes to the root.
- **Errors are tags; the root declares them as a type** (human asked: "trust typeof an error on the client so we don't need to share code"). `Boundary.root({ errors: Boundary.errors<AppError>() })` with `type AppError = Boundary.RpcErrors<typeof DocRpcs>` (a phantom, empty at runtime), then `Boundary.catchErrors(parent, { tags: ["Forbidden"] })`. `tags` is checked against the universe's tags (`Catchable`, so a typo gets TS's "Did you mean"), and against `TagChecks`: `AtLeastOneTag`, `AlreadyHandledAbove`, `TagSharedByMoreThanOneError` (tag matching can't tell two such errors apart). The fallback's `error` is `Extract<U, { _tag: T }>`. A hook rejects a query whose error carries a caught tag under a type the universe doesn't have (`CaughtAsAnotherType`). Boundary and component modules import errors with `import type` only; the RPC client still ships the group's schemas. Trust: RPC failures are decoded instances; a hand-written Effect can lie by cast, so validate where it's built. Runtime matching is `_tag` membership; a non-string or missing `_tag` is uncaught.
- **Boundaries are a chain of triples, React-style** (human asked for tuples): `const [Session, useSession, useSessionResult] = Boundary.catchErrors(App, { name, tags, fallback })`. Element 0 is the Provider component and the boundary's handle (types under `TypeId`, runtime state in a module `WeakMap`, `displayName` for DevTools; a function's `name` is read-only). The types come from the chain a component reads through, so they are only true if it is mounted above: every hook checks its boundary is above it, and every Provider checks its parent. Routing follows the chain read through, not what happens to be mounted.
- **Two hooks** (human asked, replacing the earlier one-hook conditional return, which needed each query to list its errors' schemas at runtime): `useSessionResult(query)` always returns `Result<A, Exclude<E, { _tag: Handled }>>`; `useSession(query)` returns `A` and compiles only when nothing is left (an `UnhandledErrors` brand on its parameter names the tags). So the runtime never needs to know what's left, and `Query.make` / `Mutation.make` infer `E` from the Effect. If the data hook gets a failure anyway (a lying Effect), it goes to the root.
- **Mutations: `Boundary.useRun(Session)`**, not the spec's `useSession.useRun()`: the React Compiler (and its lint) treats any property of a `use…` function as a hook used as a value, and skips the component. `run(Mutation.make({ effect }))` always resolves with a `Result` of what's left; caught failures go to their boundary and the promise never settles.
- A query's services must be the root client's. `Boundary.root({ onCaught })` reports each failure a boundary of the chain renders its fallback for, from `componentDidCatch`, for apps that don't own `createRoot` (the docs site); `Boundary.caughtBy` does the same from `onCaughtError`.
- `catchErrors`, not `catch` (the lint reads `.catch(` as a promise chain). `Effect.flatMap(Service, …)`, not `Service.use(…)` (rules-of-hooks reads `.use`).
- Queries have no retry or timeout options: write them on the Effect, and the error type follows. Only `staleTime` is the cache's.
- Requests run with the cache's services under the latest reader's, so a test's `TestClock` reaches them.
- Listeners are kept by hash, apart from entries, so a hook subscribes by `query.hash` and needs no memoized query.
- The snapshot promise records its `status` like React's thenables, so readers call `use()` on every render (skipping it once settled made React warn).
- The demo's "Type errors" tab is generated: `scripts/type-errors.ts` runs tsc over `type-errors/*.tsx` (`.fails.tsx` must fail, `.compiles.tsx` must pass), and `typecheck` runs it with `--check`.
- Lost, for now: SSR and hydration (typed failures would need the RPC group's schemas to cross the wire as instances); paged queries; devtools.
