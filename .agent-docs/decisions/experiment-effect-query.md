# Experiment: effect-query, typed error boundaries on an Effect-only cache (human asked, agent designed)

- Human: a raf-query-like library built only on Effect / Effect RPC, with type-safe error boundaries inspired by result-rpc (catch a generic error such as auth higher up, narrower ones further down), more Effect-native; competing options as separate PRs with interactive demos that show exhaustive errors, type errors for unhandled ones, and that a fully handled chain can't produce an error.
- Lives in `.experimental/effect-query/` (`package/`, `demo/` on port 3010). Effect's own `useAtomSuspense` throws `Cause.squash` to an untyped boundary, so there was nothing to reuse.

Agent decisions:

- **The cache keeps each query's `Exit`**, so a failure keeps its whole `Cause`. Routing reads it: `Cause.findError` finds a typed failure, which goes to the innermost boundary in the chain whose schemas accept it (`Schema.is`), or back to the component. A cause without one (defects, interrupts) goes to the root. Matching uses schemas, not just `_tag`.
- **Boundaries are a chain of pairs, React-style** (human asked for tuples): `const [Session, useSession] = Boundary.catchErrors(App, { name, errors, fallback })`. Element 0 is the Provider component and the boundary's handle (types under `TypeId`, runtime state in a module `WeakMap`, `displayName` for DevTools; a function's `name` is read-only). Element 1 is the hook. The shape is shared with Options B and C, apart from the two deviations below. The types come from the chain a component reads through, so they are only true if it is mounted above: every hook checks its boundary is above it, and every Provider checks its parent. Routing follows the chain read through, not what happens to be mounted.
- **One hook, conditional return** (human asked): `Read<A, E, Handled>` is `A` when the chain catches every error, else `Result<A, Exclude<E, Handled>>`. It replaced `use` / `useResult` / `Exhausted`: "type error if you don't handle one" is reading `.title` off the `Result`, or a non-exhaustive `Match.valueTags`.
- **Queries and mutations list their errors' schemas** (agent, forced by the hook): whether a read returns `A` or a `Result` depends on what the chain leaves, which only the types know, and they're gone at runtime. So `Query.make({ effect, errors: [Forbidden, …] })`, like an `Rpc`'s `error`: the schemas are the error type, and the Effect must fail with nothing else. The hook compares them to the chain's by identity. Lost: inferring `E` from the Effect and checking the list against it (TypeScript fixes `E` while contextually typing the array, and inference collapses), and a `Result` at runtime always (the type would lie). It also gives SSR the schemas typed failures need.
- **Mutations: `Boundary.useRun(Session)`**, not the spec's `useSession.useRun()`: the React Compiler (and its lint) treats any property of a `use…` function as a hook used as a value, and skips the component. `run(Mutation.make({ effect, errors }))` resolves with `Read<…>`; caught failures go to their boundary and the promise never settles.
- `catchErrors` rejects errors a boundary above catches (`NotYetHandled`). A query's services must be the root client's. `Boundary.root({ onCaught })` reports each failure a boundary of the chain renders its fallback for, from `componentDidCatch`, for apps that don't own `createRoot` (the docs site); `Boundary.caughtBy` does the same from `onCaughtError`.
- `catchErrors`, not `catch` (the lint reads `.catch(` as a promise chain). `Effect.flatMap(Service, …)`, not `Service.use(…)` (rules-of-hooks reads `.use`).
- Queries have no retry or timeout options: write them on the Effect, and the error type follows. Only `staleTime` is the cache's.
- Requests run with the cache's services under the latest reader's, so a test's `TestClock` reaches them.
- Listeners are kept by hash, apart from entries, so a hook subscribes by `query.hash` and needs no memoized query.
- The snapshot promise records its `status` like React's thenables, so readers call `use()` on every render (skipping it once settled made React warn).
- The demo's "Type errors" tab is generated: `scripts/type-errors.ts` runs tsc over `type-errors/*.tsx` (`.fails.tsx` must fail, `.compiles.tsx` must pass), and `typecheck` runs it with `--check`.
- Lost, for now: SSR and hydration (typed failures would need the query's schemas to cross the wire); paged queries; devtools.
