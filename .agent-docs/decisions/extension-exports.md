# The main entries export only what a plugin author must name (human)

- `@raf-query/core` (and `@raf-query/react` through it) exports `plugin` and the types a package needs to write one: `Plugin`, `Operation` (the request a link gets), and `Target` / `QueryInfo` for a target over the options a plugin declares. A package that ships factories binds its builders to declarations with `bindQueryOptions` and `Optional`, or to nothing (`bindQueryOptions()`) when its factories need no plugin; `RootOf<Decl>` names a client, or a target's options, that has a plugin. `QueryClient`, `QueryClientConfig`, `CoreOptions`, `OptionsOf`, `ClientFor`, `Clock` (the testing docs write a fake one), the builders' types, and the built-in plugins' declarations (`Retry`, `Polling`, `FocusRefetch`, `ReconnectRefetch`) and `Recommended` are public for apps.
- Internal, in `@raf-query/core/internal`: `Decl`, `RootTypes`, `NoPlugins`, `Root`, `RootOfPlugins`, `SetsOf`, `AnyPlugin`, `ClientEvent`, `systemClock`, `EntryState`, `AnyFactory`, `AnyTarget`. `@raf-query/react` imports the ones it needs from there. They stay exported there so declaration emit can still name them.
- The test: `packages/core/src/extension.test-d.ts` writes a plugin with a link, a feature that declares an option and subscribes to the client, a plugin that gives `queryFn` context, a target, and a package's own factories bound to `Reports & Optional<Retry>`, importing only from `./index.ts`.
- Lost: one flat public list of every type behind root typing (and an `/extend` subpath for it, which would have been a second entry for the same few names).
- Docs: `www/content/api-reference.md`, `www/content/plugins.md#writing-a-plugin` and `#binding-a-library-to-plugins`.
