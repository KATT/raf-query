# The main entries export only what a plugin author must name (human)

- `@raf-query/core` (and `@raf-query/react` through it) exports `part` and the types a package needs to write one: `Part`, `Operation` (the request a link gets), and `Target` / `QueryInfo` for a target over the options a part declares. A package that ships factories binds its builders to declarations with `bindQueryOptions` and `Optional`. `QueryClient`, `QueryClientConfig`, `CoreOptions`, `OptionsOf`, `ClientFor`, `Clock` (the testing docs write a fake one), the builders' types, and the built-in parts' declarations (`Retry`, `Polling`, `FocusRefetch`, `ReconnectRefetch`) and `Recommended` are public for apps.
- Internal, in `@raf-query/core/internal`: `Decl`, `RootTypes`, `NoParts`, `Root`, `RootOf`, `RootOfParts`, `SetsOf`, `AnyPart`, `ClientEvent`, `systemClock`, `EntryState`, `AnyFactory`, `AnyTarget`. `@raf-query/react` imports the ones it needs from there. They stay exported there so declaration emit can still name them.
- The test: `packages/core/src/extension.test-d.ts` writes a part with a link, a feature that declares an option and subscribes to the client, a part that gives `queryFn` context, a target, and a package's own factories bound to `Reports & Optional<Retry>`, importing only from `./index.ts`.
- Lost: one flat public list of every type behind root typing (and an `/extend` subpath for it, which would have been a second entry for the same few names).
- Docs: `www/content/api-reference.md`, `www/content/links-and-features.md#parts` and `#binding-a-library-to-parts`.
