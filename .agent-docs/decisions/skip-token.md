# No enabled; skipToken skips a load entry; ssr: false for browser-only data (human)

- Decision: queries have no `enabled` option. `load(qc, { drafts: cond ? prefetch(draftsQuery, input) : skipToken })` starts nothing for that name: its handle is `undefined` (typed `QueryHandle<F> | undefined`) and `data` has no key for it. Components render the reader only when there's a handle; `useQuery(factory, handle)` still requires one.
- Why: handles come from loaders, so the loader is where a query is or isn't started; a query that exists but is off has no place in that model. `enabled` waiting for input stays out: the route owns the input.
- **Browser-only data** (permission, push subscription, `localStorage`) is the one environment condition, so it's a query option: `ssr: false` (human, 2026-11-10). A server client never starts it (`isBrowserOnly` in `entry.ts` short-circuits `fetchEntry`), so it's idle and `canDehydrate` never sends it. `load`'s `prefetch` returns its handle as usual, so loaders return handles for it on both sides; `swr` / `revalidate` reject on the server without data (the server can never have it). A server read gets `browserRender` (`use-query.ts` `leftToBrowser`), the `BAILOUT_TO_CLIENT_SIDE_RENDERING` rejection server components use; the browser's first read starts it without the waterfall warning.
- Why `ssr: false` over the `useHydrated()` + `waterfallHandle` pattern: that pattern needs a child component per read (hooks can't be conditional), builds handles outside loaders (so loader data and props differ per environment), and every app re-derived it. Apps that faked it with a link holding the request pending on the server hung any `use()` read during SSR.
- Cost, documented in `ssr-and-hydration.md#browser-only-queries`: a `use()` read on the server rejects. Next.js ignores the digest; Start logs it to `onError`, and React Router's default `entry.server.tsx` answers 500 for one outside every Suspense boundary. So the docs read browser-only queries by `status`, or under a Suspense boundary.
- Lost: the `enabled` boolean and `QueryDisabledError`; a server placeholder from the `queryFn` (`null` on the server: the server caches and sends it, and nothing refetches it in the browser).
