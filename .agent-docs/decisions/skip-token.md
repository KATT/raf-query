# No enabled; skipToken skips a load entry (human)

- Decision: queries have no `enabled` option. `load(qc, { drafts: cond ? prefetch(draftsQuery, input) : skipToken })` starts nothing for that name: its handle is `undefined` (typed `QueryHandle<F> | undefined`) and `data` has no key for it. Components render the reader only when there's a handle; `useQuery(factory, handle)` still requires one.
- Why: handles come from loaders, so the loader is where a query is or isn't started; a query that exists but is off has no place in that model. A disabled query also needed its own server read path (a rejected read, `QueryDisabledError` from `load`, skipped in `dehydrate`), and Start and React Router logged or 500'd on it.
- Browser-only data (permission, push subscription, `localStorage`) has no loader entry: a component that renders after TanStack Router's `useHydrated()` builds a `waterfallHandle` once (`useState(() => waterfallHandle(…))`) in a child that reads it, so the `queryFn` never runs on the server. Don't return a placeholder (`null`) from the `queryFn` on the server instead: the server caches and sends it, and the browser never replaces it, since nothing refetches on mount.
- Lost: the `enabled` boolean (`enabled: false`, `enabled: typeof window !== "undefined"`) and `QueryDisabledError`. `enabled` waiting for input stays out: the route owns the input.
