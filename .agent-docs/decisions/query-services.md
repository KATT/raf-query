# Services channel for queries (agent, human asked)

Human: make the codebase Effect-native, inspired by [voidhashcom/effect-query](https://github.com/voidhashcom/effect-query). Ported the effect-atom experiment's services design onto the own-engine core.

- **`queryFn` Effects may need services**: `QueryFnResult<TData, TError, TServices>`, threaded through `QueryOptions` / `InfiniteQueryOptions` / `queryOptions` / `infiniteQueryOptions`; `ServicesOf<TFactory>` reads them (`never` for promises and for the erased `QueryFactory`).
- **The options carry a type-only `[servicesType]` field** (like handles' `[factoryType]`). The `queryFn` return type can't carry the requirement: with `unknown` data, `QueryFnResult<unknown, …>` is `unknown`, so anything is assignable. `QueryFactory<TServices = unknown>` returns only `kind` / `queryKey` (plus the phantom when `TServices` isn't `unknown`): TS infers an inline factory's `queryOptions` type arguments from the constraint's return type, and a `queryFn` or phantom returning `unknown` there inferred `unknown` services.
- **Which services a request gets**: the client's or cache's `EffectServices` context (`fromContext` / `fromLayer`, or the `/effect` `make`'s own context), merged with the context of the latest Effect verb that called for the entry (`provideCaller` in `effect/services.ts`, stored on the entry with `Entry.provide`, caller wins). Effect verbs that set it, and require `ServicesOf<TFactory>`: `ensure`, `fetch`, `prefetch`, `getQuery`, `watch`, `Query.fetch`. Everything else that starts a request (Promise verbs, `getQueryUnsafe` + `readUnsafe`, commands, polling, focus/reconnect, `invalidate`, `reset`) reuses the stored context. The caller's `Scope` is omitted (a request outlives its caller); its `ParentSpan` is kept, so a `withSpan` inside the `queryFn` nests under the latest caller's span.
- `callQueryFn` (`request.ts`) runs one attempt: a value or promise becomes an `Outcome`; an Effect goes to `services.run(effect, entry.context, signal)`, which provides the context, runs it with `runPromiseExit` and aborts on the signal; no services is a defect naming `fromLayer` / `fromContext`. Defects are logged with `console.error`. Entries erase `R` with the data type.
- **`QueryClient<TServices = never>`** takes `services?: EffectServices<TServices>` from `@raf-query/react/effect`: `fromContext(context)`, or `fromLayer(layer)` (builds the layer in its own scope via `runSync`, so the layer must be synchronous; `dispose` closes it). Keeping both in `/effect` keeps Effect out of apps without services. Every factory-taking verb is constrained to `QueryFactory<TServices>`; `qc.dispose()` disposes the services.
- **Erased client is `QueryClient<unknown>`** in `QueryClientProvider` / `useQueryClient` / `useQuery`: a hook can't know the provider's layer, and components must be able to `invalidate` a services-using factory. Clients of any `TServices` are mutually assignable (method bivariance), so integrations typed `QueryClient` accept any client unchanged. Unchecked: `useQuery` on a client missing a service dies at request time.
