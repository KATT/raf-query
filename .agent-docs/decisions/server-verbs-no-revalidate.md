# Server verbs don't revalidate (agent)

- **Server clients don't background-revalidate in `load`** (parent agent, 2026-10-12). `prefetchEntry` / `ensureEntry` on an `isServer` client reuse cached data whatever `staleTime` says, even after an invalidation (`prefetch` in `load.ts`); with the default `staleTime: 0`, `fetchEntry` then `ensureEntry` of one query in a server component would otherwise fire a second request whose result is never rendered. `fetchEntry` waits for fresh data either way, and the browser revalidates stale data. The examples use `staleTime: 5000` for their browser clients (Start's intent preloading reruns the loader on click; Next passes the same config to `QueryProvider`), where it saves refetches of just-hydrated data.
