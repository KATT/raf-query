# Server verbs don't revalidate (agent)

- **Server clients don't background-revalidate in `load`** (parent agent, 2026-10-12). `prefetch` / `swr` on an `isServer` client reuse cached data whatever `staleTime` says, even after an invalidation (`startIfStale` in `load.ts`); with the default `staleTime: 0`, `revalidate` then `swr` of one query in a server component would otherwise fire a second request whose result is never rendered. The browser revalidates stale data.
- **`revalidate` on a server client ignores `staleTime` too** (parent agent, 2026-11-06). PR #8 makes `revalidate` wait for fresh data like `fetchQuery`; a server client belongs to one request, so data it fetched is fresh for that request, and refetching it past `staleTime` only repeats a request whose result is never rendered. An invalidation still makes it refetch (`isFresh` in `load.ts`), so a server action's render after a write sees the write. Test: `load.test.ts` ("reuses a server request's data in a revalidate entry until a write invalidates it"). The examples use `staleTime: 5000` for their browser clients (Start's intent preloading reruns the loader on click; Next builds its client components' client from the same config), where it saves refetches of just-hydrated data.
