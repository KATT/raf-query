# The quick start is tRPC's blog example, and plural lists page for real (human)

- The quick start (`www/content/quick-start.md`) follows the blog in [tRPC's handles docs](https://trpc.io/docs/client/tanstack-react-query/handles): a post the loader waits for (`swr(postQuery, { slug })`), the post's comments as a real paged query the loader doesn't wait for (`prefetch(commentsQuery, { slug })`, read with `useInfiniteQuery` and a "Load more" button), adding a comment as the write (a plain React action, then `invalidateMany(queryClient, [[commentsQuery, { slug }]])`), and the author as the waterfall, because `authorQuery({ id: post.authorId })` needs the post. The input stays `slug`.
- Samples: the queries are `www/samples/react-router/app/queries.ts#home`, shown as `queries.ts`. Setup, starting and reading are [framework tabs](./docs-framework-tabs.md) of each app's files (`tanstack-start/src/routes/posts.$slug.tsx`, `nextjs/src/app/(blog)/…`, `react-router/app/routes/posts.$slug.tsx`). Adding a comment is `tanstack-start/src/routes/posts.$slug.tsx#add-comment`, which is plain React. The request waterfalls page uses the author as its dependent query.
- **Plural lists page for real** (human): a list a reader would expect to page is `infiniteQueryOptions`, like tRPC's infinite queries. It starts from the first page param (`cursor` `0`), the API returns a `nextCursor` computed from the data (`null` only on the last page), and the reader uses `useInfiniteQuery` + `use()` with a "Load more" button that goes away after the last page. Never a hard-coded `nextCursor: null`. Only a list with nothing a reader would expect to page stays a plain `queryOptions` list; when unsure, page it. `setData` / optimistic updates on a paged list patch `pages` and keep `pageParams`.
- Where: the demos (`www/src/demos/{caching,cancellation,invalidation,optimistic-updates,starting-queries,waterfalls}.tsx`, with `pageOf` in `demo-kit/fixtures.ts` and `LoadMoreButton` in `demo-kit/controls.tsx`), `feedQuery()` in the tanstack-start samples (`listPostPage` in `api.ts`, its post titles patched by `docs/mutations.ts`), and the query keys / query functions / one-input-serializable samples.
- Lost: a quick start on a fake-paged `todosQuery` with an `add-todo` form; fake paging (one page with `nextCursor: null`); and plain `queryOptions` lists for plural data in the demos and samples.
