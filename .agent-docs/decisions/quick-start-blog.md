# The quick start is tRPC's blog example, and lists never fake paging (human)

- The quick start (`www/content/quick-start.md`) follows the blog in [tRPC's handles docs](https://trpc.io/docs/client/tanstack-react-query/handles): a post the loader waits for (`swr(postQuery, { slug })`), the post's comments as a real paged query the loader doesn't wait for (`prefetch(commentsQuery, { slug })`, read with `useInfiniteQuery` and a "Load more" button), adding a comment as the write (a plain React action, then `invalidateMany(queryClient, [[commentsQuery, { slug }]])`), and the author as the waterfall, because `authorQuery({ id: post.authorId })` needs the post. The input stays `slug`.
- Samples: `www/samples/tanstack-start/src/queries.ts#home` (groups, `postQuery`, `commentsQuery`) and `src/routes/posts.$slug.tsx` (`#route`, `#component`, `#add-comment`). The request waterfalls page uses the author as its dependent query.
- **No fake paging anywhere** (human): a list that isn't really paged is a plain `queryOptions` list, never `infiniteQueryOptions` with `nextCursor: null`. A paged list returns a real cursor. Todos stay only where a page is about todos (TanStack's query keys / functions ports, mutations, caching and invalidation demos), as a plain `todosQuery()` list.
- Lost: a quick start on a fake-paged `todosQuery` with an `add-todo` form, and the rule that every plural query in the samples and demos is `infiniteQueryOptions` (lists that returned the whole array became one page with `nextCursor: null`).
