# Homepage framework mode toggle (human asked)

- A **pill docked above the hero code**: `position: absolute` in `#hero-code`'s reserved `padding-top` (inside the hero's `overflow-hidden`), centered on the code. While you scroll (desktop) it drifts toward the viewport center; when its spot reaches the header (`header.bottom + 8`, under the sticky menu, `z-30` vs header `z-40`) it snaps to `position: fixed` there. At the **bottom of `#how-it-works`** its `top` is capped so it stops sliding down and leaves with that section — no fade. On small screens it stays centered on the code, with the same snap. The math is the pure `frameworkModeBarLayout` (`www/src/framework-mode-bar-layout.ts`). Lost: a full-width sticky bar (heavy), an always-centered sticky pill under the header (left the code without a control), a `fixed` overlay inset into the code (covered its first lines), and fading out at `#principles` (felt like it vanished).
- The choice is `?mode=nextjs` on `/`; TanStack Start omits the param. `stripSearchParams(homeSearchDefaults)` keeps `/` from rewriting to `?mode=tanstack-start` when Zod fills the default.
- Each mode's samples are `sample:` imports from `www/samples/tanstack-start` or `www/samples/nextjs`; the route picks which set to show. Prose for the walkthrough steps switches with the mode.
- **Next.js samples** show the App Router file split (server page vs client `"use client"` module). They use `prefetch` + Suspense — not `ensure` (that verb fits loaders; in RSC, prefer `prefetch` for streamed client reads and `fetch` when the server component renders the data itself).
- The site is static HTML: `/` is prerendered as TanStack Start. After mount, the client follows `?mode=`. Prerender skips crawled `?…` URLs (`www/vite.config.ts`).
- Lost: one sample with in-block tabs (harder to share a deep link), and a site-wide preference (this toggle is homepage-only until more docs samples need it).
