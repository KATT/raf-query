# Builders bound once per client, with no bundle penalty (human; names agent)

- **(human)** A query's options and its `queryFn`'s context are typed per client: a client's root is what its plugins declare ([parts-options-context.md](./parts-options-context.md)). An app binds the root once, and factories never name it. Binding must cost nothing in apps that don't use every builder.
- **A builder only comes from a binder** ([plugins-and-bound-builders.md](./plugins-and-bound-builders.md)): the packages export no `queryOptions` or `infiniteQueryOptions`.
- **One binder per builder**, each separately importable: `bindQueryOptions<Client>()`, `bindInfiniteQueryOptions<Client>()` (core), `bindUseQueryClient<Client>()` (react). `Client` is `typeof makeQueryClient`, the client type, or plugin declarations (`Retry & Polling`; a library's `Convex & Optional<Retry>`). An app binds them in its own `raf.ts` and imports the builders from there. A binder returns the plain function, cast to a type with the root fixed (`QueryOptionsBuilder<TTypes, TSets>`, `InfiniteQueryOptionsBuilder<TTypes, TSets>`, `() => QueryClient<TTypes>`). An app that binds `queryOptions` and `useQueryClient` is 0.02 kB gzip over the base, and its bundle has no paging code ([bundle-size.md](../bundle-size.md)).
- **Without a type argument**, `bindQueryOptions()` binds to `NoDecl`: the builder's root is `NoPlugins`, which every client has, so it takes the core's options only and its factories run on any client. A plugin's option on it is a type error.
- **The root is a phantom on the built options**, `"~root"?: RootTag<TTypes>` on `QueryOptions`. `RootOfFactory` (and so `ClientFor` and every verb) reads it. Users never write the field: it isn't on the input type.
- **Every bound `queryOptions` is one function**, `buildQueryOptions`, a generic arrow (`<TOptions>(options: TOptions) => options`) that `bindQueryOptions` casts to `QueryOptionsBuilder<RootOf<T>, SetsOf<T>>`, so the overloads are written once, on the builder's type. `buildInfiniteQueryOptions` is the one function behind every bound `infiniteQueryOptions`.
- **(agent) Names: `bind*`.** The proposal was `*For` (`useQueryClientFor`). A binder whose name starts with `use` reads as a hook to the Rules of Hooks lint and the React Compiler, and it's called at module level, so `bindUseQueryClient` can't start with `use`; `bind` then names all three the same way. `bindUseQueryClient` lives in `bind.ts`, which has no `"use client"`, so a `raf.ts` that a server component imports can call it.
- Lost: `def: defType<typeof makeQueryClient>()` in every factory (typos compiled wherever it was left out, and `useQueryClient()` returned a client of any root); `createRoot()` returning `{ queryOptions, infiniteQueryOptions, useQueryClient }`, whose object keeps every builder in every bundle; a global `Register`, which allows one root per program.
- Every app in the repo has a `raf.ts` bound to its client factory, and its factories, components and loaders use it: the example apps (`examples/*/src/raf.ts`, `examples/react-router/app/raf.ts`), the docs' sample apps (`www/samples/*/src/raf.ts`, `app/raf.ts`), and the docs site (`www/src/raf.ts` for its own queries, `www/src/demo-kit/client.ts` for the demos' client).
- Where: `packages/core/src/options.ts`, `infinite/infinite.ts`, `root.ts`; `packages/react/src/bind.ts`; types in `packages/core/src/types.test-d.ts` and `packages/react/src/hooks.test-d.tsx`; fixture `tooling/bundle-size/fixtures/bound.tsx`.
