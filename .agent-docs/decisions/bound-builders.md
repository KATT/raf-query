# Builders bound once per client, with no bundle penalty (human; names agent)

- **(human)** A query's options and its `queryFn`'s context are typed per client: a client's root is what its parts declare ([parts-options-context.md](./parts-options-context.md)). An app binds the root once, and factories never name it. Binding must cost nothing in apps that don't use every builder.
- **One binder per builder**, each separately importable: `bindQueryOptions<Client>()`, `bindInfiniteQueryOptions<Client>()` (core), `bindUseQueryClient<Client>()` (react). `Client` is `typeof makeQueryClient`, the client type, or part declarations (`Retry & Polling`; a library's `Convex & Optional<Retry>`). An app binds them in its own `raf.ts` and imports the builders from there. A binder returns the plain function, cast to a type with the root fixed (`QueryOptionsBuilder<TTypes, TSets>`, `InfiniteQueryOptionsBuilder<TTypes, TSets>`, `() => QueryClient<TTypes>`). The binders add 22 B gzip to an app that binds `queryOptions` and `useQueryClient`, and that app's bundle has no paging code ([bundle-size.md](../bundle-size.md)).
- **The root is a phantom on the built options**, `"~root"?: RootTag<TTypes>` on `QueryOptions`. `RootOfFactory` (and so `ClientFor` and every verb) reads it. An unbound builder's root is `NoParts`, which every client has, so its factories run on any client. Users never write the field: it isn't on the input type.
- **The unbound builders take the core's options only.** A part's option on them is a type error, so every factory that sets one is built with a bound builder.
- **`queryOptions` is a `const` typed `QueryOptionsBuilder<NoParts>`**, so its overloads are written once and the bound builder reuses them. Its value is a generic arrow (`<TOptions>(options: TOptions) => options`), assigned without a cast: an `as` cast on the arrow keeps parentheses in the minified output (+5 B), and a function aliased by a `const` keeps the alias (+10 B).
- **(agent) Names: `bind*`.** The proposal was `*For` (`useQueryClientFor`). A binder whose name starts with `use` reads as a hook to the Rules of Hooks lint and the React Compiler, and it's called at module level, so `bindUseQueryClient` can't start with `use`; `bind` then names all three the same way. `bindUseQueryClient` lives in `bind.ts`, which has no `"use client"`, so a `raf.ts` that a server component imports can call it.
- Lost: `def: defType<typeof makeQueryClient>()` in every factory (typos compiled wherever it was left out, and `useQueryClient()` returned a client of any root); `createRoot()` returning `{ queryOptions, infiniteQueryOptions, useQueryClient }`, whose object keeps every builder in every bundle; a global `Register`, which allows one root per program.
- The example apps and the docs' sample apps build their `queries.ts` with the unbound builders: those factories set core options only. The docs samples that set a part's option import the builders from `www/samples/tanstack-start/src/raf.ts`, and the docs site's demos from `www/src/demo-kit/client.ts`.
- Where: `packages/core/src/options.ts`, `infinite/infinite.ts`, `root.ts`; `packages/react/src/bind.ts`; types in `packages/core/src/types.test-d.ts` and `packages/react/src/hooks.test-d.tsx`; fixture `tooling/bundle-size/fixtures/bound.tsx`.
