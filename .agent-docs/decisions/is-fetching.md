# `isFetching` / `useIsFetching` (agent; keep for compat human asked)

- **Keep `useIsFetching`** for TanStack Query compatibility (human, PR #80). Prefer the router's pending UI for navigations and per-query `controls.isFetching` for background refetches; the hook is for the rare global count. Docs steer there and link the Start / Next variants ([Background fetching indicators](../../www/content/background-fetching-indicators.md), [TanStack Start § Pending UI](../../www/content/tanstack-start.md), [React Server Components § Pending UI](../../www/content/react-server-components.md)).
- **`isFetching(client, target?)` / `useIsFetching(target?)`**, like TanStack's, for that global count: the number of entries with a request in flight, matched like the invalidate verbs (a factory, a group or a target; none → every entry). No stream variant: `client.subscribe` plus `isFetching` covers it.
- The hook is `useSyncExternalStore` on `client.subscribe` with the count as snapshot, server snapshot included, as TanStack does. It listens for `updated` and `removed` events, which the core batches in a microtask, so a fetch started while another component renders doesn't update this one mid-render.
- Where: `packages/core/src/verbs.ts`, `packages/react/src/use-is-fetching.ts`.
