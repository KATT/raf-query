# `isFetching` / `useIsFetching` (agent)

- **`isFetching(filter?)` / `useIsFetching(filter?)`** (parent agent, 2026-10-12), like TanStack's, for global loading indicators: the number of entries with a request in flight, matched with the same `match` as `invalidate` / `reset` / `remove` (no filter → every entry). `QueryCache` has `isFetching` (Effect) and `isFetchingUnsafe` (renders); `QueryClient.isFetching` calls the latter. No Stream variant: `events` plus `isFetching` covers it. The hook is `useSyncExternalStore` on `qc.subscribe` with the count as snapshot; the server snapshot is `0` (TanStack reuses the count), so server HTML and the hydrating render agree whatever is in flight on either side. Cache events fire synchronously, also while another component renders (a `readUnsafe` that starts a fetch), so the hook calls `onStoreChange` in a microtask, once per batch, as `devtools-store.ts` does; calling it synchronously makes React warn "Cannot update a component while rendering a different component" (covered by a test).
