# Two packages, React-agnostic core

- `@raf-query/core` (framework-agnostic, mirrors `@tanstack/query-core`) and `@raf-query/react` (bindings, re-exports core — apps install only this).
- **Core is Promise-based with an Effect entry** (human: cut Effect except in one entrypoint; see [promise-engine.md](./promise-engine.md)). `@raf-query/core` exports the Promise `QueryCache` / `Query` / `QueryObserver` modules; `@raf-query/core/effect` has the `QueryCache` service, Effect verbs and Streams over the same cache. `createQueryClient` (a plain object of closures over a core cache; no class), `dehydrate(client)` / `hydrate(client)` and `allKeyed` live in `@raf-query/react` (`src/client.ts`), which re-exports `/effect` as `@raf-query/react/effect`. Sync access during render follows Effect's `*Unsafe` naming (`getQueryUnsafe`, `Query.getUnsafe`, `Query.readUnsafe`, `Query.subscribeUnsafe`).
- Framework integrations are subpath exports of `@raf-query/react` (`/tanstack-router`, `/rsc`, `/next`), not separate packages.
- **Lockstep versions:** both packages always share a version and release together.
- `@raf-query/react` depends on `@raf-query/core` via `workspace:*`, which `pnpm pack` publishes as the exact lockstep version. `react` is a peer (`^19.2.0`).
- **`effect` is a required peer (`^4.0.0`) of both packages**, plus a `catalog:` devDependency for the workspace; only the `/effect` entries import it. A regular dependency, even a caret range, leaves deduping to the package manager, and a second Effect splits module-level state (service tags, default runtime) as well as adding size. npm, pnpm and Bun auto-install required peers, so promise-only apps still need no extra step; Yarn users add `effect` themselves. The `tsc` build emits imports as written, so the dev copy isn't bundled.
