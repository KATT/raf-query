# The examples put the loader verb in the URL, one route folder per verb (human)

- Human: let the examples switch between the three ways a loader starts a query — "it's about ensure/prefetch/fetch", not REST vs RPC — by putting the choice in the URL (`/prefetch/issues`, `/swr/issues/3`, `/revalidate/issues/3`). The verbs and routes follow the `load` builder names ([load-builder-names.md](./load-builder-names.md)).
- **Why the URL**: the verb is what the examples exist to show, so it is shareable, survives a reload, and SSR renders with it. A cookie setting would hide it.
- **WET, not a `$verb` param** (human: "each type should be self-contained inside of the route rather than having generic abstractions … a human needs to be able to read the examples and follow along easily"; "we shouldn't have a $verb route in any of the examples, it should just be WET"). Each app has `prefetch/`, `swr/` and `revalidate/` route folders with their own route files and readers. A loader calls `load` with `prefetch`, `swr` or `revalidate` itself. Every reader calls `useQuery` and then `use()` on the thenable, for every verb ([use-query-thenable.md](./use-query-thenable.md)). Lost: a `startQuery(qc, verb, …)` switch and a `useQueryData` that unwrapped either handle, which hid the one difference the examples show behind casts.
- `swr/` and `revalidate/` differ only in the verb and the loader's comment. `prefetch/` differs in its loaders: the loader has no waited-for data to check. Readers are the same on every verb. Keep the copies in step by hand.
- Unknown verbs are not-found because no route matches. Bare `/issues…` and `/` redirect to `/prefetch/…`, keeping the search.
- TanStack Start needs `defaultStaleReloadMode: "blocking"`: without it a revisit shows the last loader data and reloads in the background, so `revalidate` never visibly waits.
- On a server with a per-request client the cache is empty, so `swr` and `revalidate` wait for the same thing on a full page load. Next.js and React Router render every navigation on the server with a new client, so there `swr` waits like `revalidate` every time; the README and feature map say so.
- The header is app chrome, not a route: it reads the verb from the path (`loaderVerbOf` in `@examples/kit/lib/loader-verb`) for its list link and the Loader select (see `examples-header-toolbar.md`).
