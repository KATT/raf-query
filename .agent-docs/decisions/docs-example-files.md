# Docs examples can live in real files, included by region (human idea, agent design)

- **`<<< ./page/src/file.tsx#name` in a page** (human idea; agent picked VitePress's syntax): `www/build/snippets.ts` expands it into a `twoslash` block before rendering, so the HTML and the agent markdown (`/docs/<slug>.md`, `llms-full.txt`) both see a normal fence. `#name` picks a VS Code `// #region name` … `// #endregion`; no `#name` shows the whole file. `[title]` overrides the title and `[]` drops it.
- **The whole file compiles, only the region shows** (agent, like mdBook's `rustdoc_include`): the rest of the file goes above `// ---cut---` / below `// ---cut-after---`. Region-only includes (VitePress, Vocs, TypeDoc, remark-code-import) would compile the region on its own and lose its imports.
- **Example files mirror an app under `www/content/<page>/`** (agent): the title defaults to the path inside that folder (`src/routes/todos.tsx`), and relative imports between them work. `www/tsconfig.json` and lint include them, so `tsc` and the editor check them; `.oxlintrc.json` relaxes the rules that fight readable samples there.
- **Twoslash empties a block's virtual files after it renders** (agent): each block compiles as `<file>.<region>.twoslash.<ext>` next to the file, not at the file's own path, or later blocks importing the file see an empty module.
- **Inline `twoslash` fences still work** (agent): short one-off samples and blocks that need `// @errors` stay inline; `quick-start.md` is the first page on includes. Lost: Twoslash's `twoslash include` / `// @include:` (still in the markdown, no editor support).
