# Tests drive real queries through the public API (human asked)

- Alex (2026-11-06): every test makes a client, defines queries, mutations and groups with the public API, and drives them as an app does (`load`, `useQuery`, the verbs, actions, streams, hydration, the boundaries). It asserts what a user can observe: data, renders, request counts, errors. Coverage is 100% per package ([coverage-thresholds.md](./coverage-thresholds.md)) and comes from those scenarios.
- Tests import only what an app can import: a package's entries (`./index.ts`, `./index-react-server.ts`, the router builds) and the modules they re-export (`./hydration.ts`, `./devtools.tsx`) and the other packages by name. No `~` fields, no `@raf-query/core/internal`, no kernel modules, no `vi.mock` of our own code. Mock only the outside world: the network (a fake backend that holds requests until the test responds), the clock (`fakeClock`, `vi.useFakeTimers`), focus and online events, `NODE_ENV` (`vi.stubEnv`).
- Core's tests read through `@raf-query/react`'s hooks, as an app does. Core's `vite.config.ts` aliases `@raf-query/react` to react's source and `tsconfig.json` has the matching `paths`; it isn't a dependency, because react depends on core and pnpm refuses the workspace cycle (`ERR_PNPM_TASK_CYCLE`). knip ignores it for core.
- Type tests are `*.test-d.ts`: `tsc` checks them, vitest doesn't run them, coverage leaves them out, and they lint with the test overrides.
- A line no scenario can reach is dead code: delete it instead of unit-testing it. `istanbul`/`v8` ignore comments only for code truly unreachable from a query (a dev-only guard, say), each with its reason; there are none today.
- Prefer fewer scenarios that each show something a user sees. Delete a test that restates the implementation, checks a trivial getter, duplicates another, or pokes internals, as long as coverage stays at 100%.
