# Experimental framework example apps (human asked)

- **Each experimental framework binding gets the full issue tracker** (Svelte and Vue), matching the four React apps feature for feature, as `.experimental/<framework>/app` (`@examples/experimental-<framework>-app`). Not deployed, no CodeSandbox copy (human). The verify-examples feature map drives them; differences go in each feature's `Gotchas`. Devtools are React-only, so they have none.
- **UI is the framework's shadcn port**, vendored per app in `src/lib/components/ui` (shadcn-svelte on bits-ui; shadcn-vue on reka-ui in `src/components/ui`), styled by the shared `@examples/ui/globals.css`, so the markup and classes match the React apps. Oxlint treats the folder like the React shadcn copy.
- **SvelteKit: server `load`s, like React Router.** Each `load` makes a new query client, starts the page's queries under the URL's verb and returns the handles plus `dehydrate(qc)`; SvelteKit's serializer streams the pending promises. Svelte can't stream markup, so `prefetch` pages render skeletons and the data lands as scripts; `ensure` / `fetch` pages render with data. The loader hint uses the `server` runtime (`@examples/kit/lib/loader-verb`).
- **Kit 3 shapes the app**: `#lib/*` through `package.json` `imports` (no `$lib`), `src/params.ts` with `defineParams` and the zod `LoaderVerb` for the `[verb=verb]` matcher, `$app/env`, config inline in `vite.config.ts`. shadcn-svelte's CLI can't read the `$app/tsconfig` alias; add components with a temporary `paths` entry, then rewrite `$lib/` to `#lib/`.
- **Prefetch links** use SvelteKit's preloading: `data-sveltekit-preload-data="hover"` for intent, `preloadData` on render or when an IntersectionObserver fires; the body turns the default off.
- The in-process Hono API gets the page's cookies through `withRequest`, a synchronous request stack read by the API client's `forwardedHeaders` on the server.
- **Vue: browser loaders, like TanStack Start.** Vue has no meta-framework here, so the app owns its SSR: a Vite plugin hands dev requests to `src/server/handler.ts` (Hono: `/api/*` and the page renderer), and `src/server.ts` is the Effect production server. Each route's `meta.loader` runs in `router.beforeResolve` and its result is the page's props; `notFound` routes to the not-found page, keeping the URL. The first browser navigation reuses the server's loader result.
- **Vue streaming**: the server dehydrates before `renderToString` (a query settling in between would make the client's HTML differ), then streams each pending query's result as a `rafQueryBoot.settle` script. The client settles those promises only after mounting, so hydration sees the same pending state the server rendered.
- Vue's page cookies reach the in-process API through an `AsyncLocalStorage` in `server/render.ts`. Scroll to top on a push is done in `afterEach` from `history.state.position` (Vue Router's `scrollBehavior` is deprecated in v5).
