# Every docs example is a blog's posts and comments (human)

- Every example in the docs (pages, samples under `www/samples`, interactive demos under `www/src/demos`) uses one domain: a blog's posts, their comments, and the post's author where a page needs a dependent query. No todos, issues, invoices, projects, inbox messages, builds or stats dashboards.
- Why: the quick start and the homepage already use the blog, so a reader learns one model and every page builds on it.
- Plural lists page for real (see [quick-start-blog.md](./quick-start-blog.md)): `feedQuery()` (posts, from cursor `0`) and `commentsQuery({ slug })` are the paged lists; `postsQuery({ page, sort })` is the list paged by page number from the URL. Comments list newest first, so a new comment lands on the loaded first page.
- Writes: adding a comment (quick start, `docs/mutations.optimistic-updates.tsx`, the optimistic-updates demo, where it shows marked "saving" until the refetch confirms it) and editing a post's title (`docs/mutations.ts`, `setData` patching `pages` and keeping `pageParams`).
- Where: `www/samples/tanstack-start/src/{api,queries}.ts` and `src/docs/*`, `www/samples/nextjs/src`, `www/src/demos/*` with `seedPosts` / `seedComments` / `pageOf` in `demo-kit/fixtures.ts`, and the `www/content` pages that show them.
- Lost: a todo list (`todosQuery`, `TodoPage`, toggling `done`) as the samples' paged list and optimistic write; issues in the Next.js samples; invoices, a chat log, a map, builds, a user's organization and settings in the other samples; and an inbox, stats cards, a visitors chart, projects and messages in the demos.
- Supporting queries stay in the blog: the signed-in reader (`meQuery`, `_auth` routes), a post's counts, views and live readers (polling, fetching indicators), live comments (streaming), a post's push-notification state and the notification permission (browser-only queries), and search over posts.
- Not in scope: the `examples/*` apps, which are an issue tracker on purpose (see [example-apps.md](./example-apps.md)), and the docs prose that links to or describes them.
