# Every docs example is a blog's posts and comments (human)

- Every example in the docs (pages, samples under `www/samples`, interactive demos under `www/src/demos`) uses one domain: a blog's posts, their comments, and the post's author where a page needs a dependent query. No todos.
- Why: the quick start and the homepage already use the blog, so a reader learns one model and every page builds on it.
- Plural lists page for real (see [quick-start-blog.md](./quick-start-blog.md)): `feedQuery()` (posts, from cursor `0`) and `commentsQuery({ slug })` are the paged lists; `postsQuery({ page, sort })` is the list paged by page number from the URL. Comments list newest first, so a new comment lands on the loaded first page.
- Writes: adding a comment (quick start, `docs/mutations.optimistic-updates.tsx`, the optimistic-updates demo, where it shows marked "saving" until the refetch confirms it) and editing a post's title (`docs/mutations.ts`, `setData` patching `pages` and keeping `pageParams`).
- Where: `www/samples/tanstack-start/src/{api,queries}.ts` and `src/docs/*`, `www/src/demos/*` with `seedPosts` / `seedComments` / `pageOf` in `demo-kit/fixtures.ts`, and the `www/content` pages that show them.
- Lost: a todo list (`todosQuery`, `TodoPage`, toggling `done`) as the samples' paged list and optimistic write, and todos in the caching, invalidation and optimistic-updates demos.
- Still on other domains (convert when touching them): the issues / invoices / projects / messages / inbox / stats examples in `www/samples/nextjs/src/queries.ts`, `www/samples/tanstack-start/src/docs/{comparison.tsx,infinite-queries.ts,links-and-features.bind.tsx,render-optimizations.ts,testing.tsx}` and the `cancellation`, `fetching-indicators`, `infinite-scroll`, `pagination` and `polling` demos. Account, settings and build-log queries stay where a page needs a signed-in user or a stream.
- Not in scope: the `examples/*` apps, which are an issue tracker on purpose (see [example-apps.md](./example-apps.md)).
