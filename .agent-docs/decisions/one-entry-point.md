# One entry point per package (human)

- Apps import everything from `@raf-query/react` (or `@raf-query/core`): tags (`tag`, `groups()`), hydration (`dehydrate`, `dehydrateStream`, `hydrate`, `canDehydrate`, `RedactedError`) and, in react, the devtools (`QueryDevtools`, `QueryDevtoolsPanel`). The `/groups`, `/hydration` and `/devtools` subpaths are gone from both `exports` and `publishConfig.exports`, and from the pack entries.
- **Two subpaths stay.** `@raf-query/react/tanstack-router`: it imports `isRedirect` from the optional peer `@tanstack/react-router` at runtime, and its export conditions ship different code to the server and the browser ([router-browser-build.md](./router-browser-build.md)). `@raf-query/core/internal`: the kernel for `@raf-query/react` only, not a public API.
- **Costs nothing unused.** Both packages set `"sideEffects": false` (the packed `package.json` keeps it at the top level; `dist/` has no `package.json` of its own), the main entries re-export by name (`export *` only of core, itself side-effect free), and the folded modules (`core/groups`, `core/hydration`, `react/devtools`) do no work at import time: no CSS, no registration, no top-level calls. `react-server-hooks.ts`'s top-level `clientOnly()` calls are marked `/* @__PURE__ */`. `pnpm bundle-size` (and `--dist`) shows every entry that doesn't import tags, hydration or the devtools unchanged and without their markers; a fixture with `{process.env.NODE_ENV !== "production" ? <QueryDevtools /> : null}` built in production mode has no devtools code ([bundle-size.md](../bundle-size.md)).
- **`devtools.tsx` keeps `"use client"`**, and both the default and the `react-server` entry re-export it from `index-shared.ts`, so a Next.js server component layout imports `QueryDevtools` from `@raf-query/react` as a client reference.
- Lost: subpaths as the signal that a part is opt-in. The docs say it instead (`installation.md`, "One entry point"), and the bundle-size run enforces it.
