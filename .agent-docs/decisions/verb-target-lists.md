# `…Many` verbs take a list of targets (human asked)

- `invalidateMany`, `resetMany` and `removeMany` take one target, or a list: `invalidateMany(qc, [group, factory, [factory, partial], [target, param]])`. Asked so the API doesn't push apps toward `await invalidateMany(qc, a); await invalidateMany(qc, b);`, which serializes the refetches. The docs teach the list whenever more than one thing is invalidated.
- One call records every target's stamp at one `~seq`, then refetches each read entry they cover **once** (a second `invalidate` would abort the first refetch and start another) and resolves when all settle. Where: `invalidate` in `packages/core/src/entry.ts`, `stampsOf` in `verbs.ts`.
- Types: a `const` type parameter inferred through a homomorphic mapped type (`TargetList` in `verbs.ts`), so each element of an inline literal is checked on its own: partial against the factory's `PartialInput`, param against the target's, and the root through `ClientFor` / `TargetFor`, like the single-target overloads. Raw keys and strings are rejected. The list overload is the last one, so a wrong element reports its own error rather than the single-target overloads'. Tests: `types.test-d.ts` ("check each target of a list on its own", "check a list's targets against the client's root"), `verbs.test.ts`.
- `isFetching` / `useIsFetching` take one target only; nothing asked for a list there.
