# Keys, groups and targets (human asked, agent built; provisional)

- **Provisional:** the design is waiting for sign-off. `meta` flows the V3 way: links and features declare it, typed per client by builders bound once per app ([bound-builders.md](./bound-builders.md)). Everything that parses or matches keys sits behind one internal seam, `packages/core/src/keys.ts`, so it can change without touching the rest of the kernel.
- A key is plain JSON: the array a group builds, or a hand-written one ([hand-written-keys.md](./hand-written-keys.md)), hashed with sorted object fields. Keys look the same in memory, on the wire and in devtools.
- Invalidation is typed and tied to factories and targets, never raw keys: `invalidateOne(qc, factory, input)`, `invalidateMany(qc, factory, partialInput?)`, `invalidateMany(qc, group)`, `invalidateMany(qc, { where }, param?)`, or a list of these in one call ([verb-target-lists.md](./verb-target-lists.md)).
- **Groups** are callables that build flat keys, and a group target matches every key that starts with its path: see [tuple-groups-flat-keys.md](./tuple-groups-flat-keys.md). `group` is on the main entry. No `/*#__PURE__*/` in user code.
- **`where` targets** read a query's key, input, `meta` or data, and never enter keys. Tags are one, written in user code over a `meta.tags` that a setup-less feature declares: core ships no tags ([tags-userland.md](./tags-userland.md)).
- The client's types come from its parts (tRPC v12 style): links and features declare the `meta` fields they read, `createQueryClient` intersects them, and an app binds its builders to that root once (`bindQueryOptions<typeof makeQueryClient>()`, [bound-builders.md](./bound-builders.md)). No global `Register`, no module-level client.
- Lost: string or array key filters, `matchesKey`, and functions inside keys (they don't survive `structuredClone` or the wire).
- Where: `packages/core/src/keys.ts` (`group`, the matcher), `root.ts`, `verbs.ts`; types in `types.test-d.ts`.
