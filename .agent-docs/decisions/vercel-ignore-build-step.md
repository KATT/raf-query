# Vercel skips a build by diffing from the last deployment (human asked)

- `ignoreCommand` in every `vercel.json` is `sh …/tooling/vercel-ignore/ignore.sh`, run from the project's root directory. It installs `@tooling/vercel-ignore` (`install --frozen-lockfile --prod --ignore-scripts --filter …`: about 14 packages, Effect and its Node platform) and runs its `src/bin/ignore.ts`.
- The install runs the pnpm in `packageManager` through `npx`. The ignore step runs before Vercel sets up the project's pnpm, and the `pnpm` on its PATH is older and can't read this lockfile (`ERR_PNPM_BROKEN_LOCKFILE`), so with it every deployment would build (#161).
- `ignoreCommand` is capped at 256 characters; a longer one fails the deployment. Keep logic in `ignore.sh` or the Effect code. It's in Effect (human, see [effect-scope.md](./effect-scope.md)). `--prod` keeps the root's dev tooling out. `--ignore-scripts` skips the root `postinstall`, which needs that tooling. Vercel's full install afterwards still succeeds.
- It watches the project, every workspace package it reaches through `workspace:` dependencies (any dependency field, transitively, from `pnpm-workspace.yaml`'s globs), and the root install inputs (`package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` for catalog and overrides, `.npmrc`, `patches`). Deriving the list keeps it from drifting: a hand-written list misses packages such as `@examples/kit` for `www`, and the catalog.
- It diffs `$VERCEL_GIT_PREVIOUS_SHA..HEAD`, not `HEAD^..HEAD`. With `HEAD^`, a push of several commits whose tip only touches docs skips the example apps even when an earlier commit changes `packages/`.
- `VERCEL_GIT_PREVIOUS_SHA` is the last successful deployment on the project and branch, so skipped deployments don't move it. It is empty on a branch's first deployment, which is most PRs (one push). Then it fetches `main` (depth 100, public HTTPS URL) into Vercel's shallow clone and diffs from `git merge-base FETCH_HEAD HEAD`. Building on every first deployment would rebuild every app for a `www`-only PR (#154). On `main` itself an empty SHA builds.
- If the SHA isn't in Vercel's shallow clone, as after a force-push, `git diff` exits 128. Vercel documents only 0 (skip) and 1 (build), and any other code fails the deployment within about 15 seconds of starting. So every failure (install, fetch, merge-base, diff, a git command's non-zero exit) exits 1 and builds. Building too often beats skipping one that changed.
- Vercel's own "skip unaffected projects" runs first and shows as "Skipped - Not affected". It treats any change outside a workspace package (`.agent-docs/`, root files) as affecting every project, and then this step decides. A skip here shows as "Canceled by Ignored Build Step".
- Lost: `turbo query affected` (no Turborepo here); `HEAD^` (only the tip commit); a Node-built-ins script that needs no install (human wants Effect).
