# One feature map drives all three example apps (human asked, agent designed)

- Human: "build a feature map of the example projects (since they're identical)", following poteto's verification skills, and add what's missing.
- **Where**: `.agents/skills/verify-examples/`. `SKILL.md` (launch, doctor, drive, evidence, cleanup), `features/README.md` (baseline data, conventions, the feature-entry format, the sweep order), one file per feature with `Sub-features`, `How to get to it (user POV)`, `Driving it with control-examples`, `Gotchas`, and `cross-app-journeys.md` last. The shape is poteto's `create-verification-skill` (pstack). Skills go in `.agents/skills/`, not `.cursor/skills/` (human: "don't use cursor use `.agents`"), so any agent finds them.
- **One recipe per feature, run unchanged in every app** with `U` set to the app's origin. Elements are found by role and accessible name, so the apps have to keep the same names; an app that differs is either fixed or the difference goes in that feature's `Gotchas` with the reason (`cross-app-journeys.md` has the table).
- **Driver**: `scripts/control-examples.mjs`, a dependency-free DevTools protocol client (Node's global `WebSocket`) with real mouse, wheel and keyboard input. No Playwright: nothing to install, and the commands read like the user path.
- **What the map holds every app to**, React Router included: the status menu uses `onClick` (Base UI doesn't fire Radix's `onSelect`), not-found pages render inside the layout, previous/next replace the issue on screen, the Prefetch setting reaches every link with the same values, and there's a `ThemeProvider`. Every app answers 404 for `/issues/abc`, like Next.js.
- **Kept as differences**: Next.js has no "On render" prefetch (`next/link` can't) and prefetches only in production; React Router answers `curl` with 500 for a missing issue (it renders the whole page for bots before sending it).
- Keep it current: a change to something a user sees in the examples updates the matching feature file in the same PR.
