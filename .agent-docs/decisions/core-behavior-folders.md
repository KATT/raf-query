# One folder per opt-in behavior in core, with tests that document the internals (human)

- Alex wants to review how each behavior works on its own, and to read the colocated tests as author documentation of the internals. So each opt-in behavior or distinct mechanism in `packages/core/src` has a folder holding its implementation and its test: `links/retry/`, `links/timeout/`, `features/focus-refetch/`, `features/reconnect-refetch/`, `features/polling/`, `hydration/`, `infinite/`, `structural-sharing/`, `keys/` (keys and `group()`, and target matching). The map with one line per behavior is [../core-behaviors.md](../core-behaviors.md).
- The kernel stays flat: `client.ts`, `entry.ts`, `load.ts`, `verbs.ts`, `options.ts`, `root.ts`, `thenable.ts`, `subscribe.ts`, with `fail.ts`, `guards.ts`, `presets.ts`, `index.ts` and `internal.ts`. Its tests stay flat beside it (`load.test.ts`, `reading.test.ts`, `verbs.test.ts`, `streams.test.ts`, …).
- Each test file opens with a comment on how the behavior works inside: what it is (a plugin's link wraps each request through `next(op)`; a feature's `setup` gets `(client, signal)` while a provider has the client mounted), what it reads from the query's options, what it subscribes to or wraps, and what it writes to the cache. Each `describe` / `it` reads as a sentence about one behavior and drives the public API with the fake `Clock` (`testClient`), showing the setup an app writes (`testClient({ plugins: [retry()] })`, a factory with `retry: 1` from a bound builder). Helpers more than one folder uses live in `test-utils.ts` (`cached`, `counted`, `flaky`, `loadOne`).
- Streams stay in `entry.ts`: folding chunks is part of a request's run (settling at the first chunk, writing each one, failing through `failWith`), and a `streams/` module would import `write` / `failWith` / `finish` from the entry that calls it, an import cycle `knip` rejects. `streams.test.ts` documents it from the kernel's side.
- `group()` lives in `keys/keys.ts` with `hashKey`, not a `group.ts` of its own: a separate module lands later in the bundle and moved most bundle-size entries by 1 to 9 B; in `keys.ts` every entry is byte-identical to the flat layout.
- Unchanged: the public API and the package `exports` (everything on the main entry; `/internal` for bindings). Only import paths inside the package moved. The bundle-size markers name the behavior modules (`core/links/retry/retry`, `core/hydration/hydration`, …) instead of strings.
- Lost: one file per kind of plugin (`links.ts`, `features.ts`), which was shorter to scan for someone comparing the plugins with each other.
