# `useQuery`'s read-only `select` (agent)

- **Reverses the "no `select`" stance** (the "Intentional" row "keep one cached shape" in `comparison.md`), at the human's request to open a PR for each TanStack feature that could be considered. The cache still keeps one shape: `select` never writes back; it only maps what one reader sees.
- **What:** `useQuery(factory, handle, { select })`. The first slot is a `Thenable` of what `select` returns (the value itself for a `QueryHandleWithData`, a `Result` of it with `throwOnError: false`). `TSelected` is inferred from `select`'s return; `UseQuerySelectOptions<TFactory, TSelected>` types it, and `UseQueryOptions` omits the observer's untyped `select`.
- **Lives in the observer, like TanStack's `#selectFn` / `#selectResult`:** `QueryObserver.Options.select`, memoized per observer in `selection` (source promise, function, handed-out promise). Same source and function: same promise. New function or data: run again, `replaceEqualDeep` with the last value, and an equal value keeps the last promise, so the observer has nothing to notify. Putting it in the hook (a `useMemo` over the promise) would still re-render on every data change, because the observer tracks the unselected promise.
- **Pending first load:** the selection is a `pending()` thenable, settled in place when the source settles (by the source's `then`, and synchronously by the next result computed after the source settled, so `status` readers see the settle). An inline `select` while pending keeps the same promise and settles with the latest function. A suspended mount's fresh observer makes a new selection; React gives no "uncached promise" warning there (tried StrictMode, boundaries, transitions, parent re-renders while suspended).
- **Errors:** a failed first load rejects the selection with the same reason; a throwing `select` rejects it with what it threw (in Result mode that's a `Result.fail`, as a dying `queryFn` already is).
- **`whilePending: "previous"`** selects from the previous query's data; **paged** factories select from `{ pages, pageParams }` and keep paging controls.
- **Lost:** TanStack keeping the last selected data and moving to `status: "error"` when `select` throws (there's no status field; rejecting is the promise-first equivalent). `select` on `qc.ensure` / handles (the handle is the cache's view; reads shape it). Respecting `structuralSharing: false` for the selection (it's always shared; selections are small, and sharing is what keeps equal selections from re-rendering).
- **Files:** `packages/core/src/observer.ts`, `packages/core/src/controls.ts`, `packages/react/src/use-query.ts`; tests in `observer.test.ts`, `use-query.test.tsx`, `types.test.ts`; docs in `www/content/render-optimizations.md#selecting-part-of-the-data`, `reading-queries.md`, `api-reference.md`, `comparison.md`.
