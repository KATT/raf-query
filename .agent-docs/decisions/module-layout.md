# Module layout (agent, human asked)

Human, on the first pass: "query.ts is a bunch of classes with ugly `implements` and custom observers… is this how you write complex effect code well?" The layout now follows `.repos/effect` (`Cache.ts`, `Deferred.ts`, `reactivity/AtomRegistry.ts`):

- **Core's public modules are namespaces** (`export * as Query / QueryCache / QueryObserver` in `index.ts`; `/effect` adds `Platform` and Effect versions of the three in `effect.ts`), each an interface + `TypeId` + guard (`isQuery`, `isQueryCache`, `isQueryObserver`) + functions. Option and key helpers (`queryOptions`, `hashKey`) stay flat: they're the app-facing API. `import-x/no-namespace` is off (human: "you can kill that lint rule").
- **`Query` is a data type, not a class**: `query.ts` is the public facade (Promise verbs plus `*Unsafe` readers; `effect/query.ts` re-exports those and adds Effect verbs, `Query.fetch` `dual`); `entry.ts` holds the implementation as plain objects and functions over them. Each entry stores its command functions once (`entry.commands`), so `Query.refetch(q)` keeps one identity and the observer's shallow compare holds.
- **Core's `QueryCache` is an opaque handle with module functions** (`cache.ts`: `make(config)`, then `fetch(cache, …)` etc.); the `/effect` `QueryCache` is a `Context.Service` built by `make(config): Effect<QueryCache, never, Scope>` or `layer(config)`, or wrapped around an existing cache with `fromCache`. Services use methods; data types use module functions, as in Effect. React's `QueryClient` owns a core cache (`qc.cache`) and only delegates.
- **Time is an injected `Clock`** (`clock.ts`: `now()`, `schedule(cb, ms) => cancel`; default `systemClock`), **the page is a `Platform`** (`platform.ts`; `globalPlatform` reads `window` / `document` / `navigator` lazily, so React tests' `vi.stubGlobal` still works). The `/effect` `make` passes a `Clock` over Effect's and the `Platform` reference, so core tests run on `it.effect`'s TestClock with `fakePlatform()` (`test-utils.ts`). React tests keep vi fake timers over `systemClock`.
- Sync listener sets and microtask batching (`notify.ts`) for `useSyncExternalStore` — `SubscriptionRef` updates through a semaphore and has no sync subscribe; Effect's own `AtomRegistry` keeps plain listener sets for the same reason. The observer's own listener set and `trackedProps` are plain for the same reason.
- **`QueryObserver` is a data type too**. `observer.ts` holds the interface and sync functions for renders (`makeUnsafe`, `getUnsafe`, `getOptimisticResultUnsafe`, `setOptionsUnsafe`, `subscribeUnsafe`, `trackResult`, `trackProp`); `effect/observer.ts` adds `make`, `get` and `changes` (a `Stream` of results). While it has listeners, the observer holds a subscription `{ close, stopPolling }` registered in its entry's `onRemove`, and the `refetchInterval` poll is a `clock.schedule` timer (an interval change replaces the timer, keeping the subscription). Switching queries or losing the last listener closes it; so does the entry leaving the cache, so a removed entry's readers stop polling.
- Rejected for the observer: resubscribing on an interval change (churns `gc` / `observers` events); parenting the subscription on the cache (polling would outlive a removed entry). `allKeyed` is a ponyfill of a Promise API.
- Not adopted: rebuilding on `effect/reactivity` (`Atom.family`, `swr`, `setIdleTTL`, `Hydration`, `@effect/atom-react`). It covers much of raf-query but is `@stability unstable` and differs on promise identity, ensured handles, invalidate-waits-for-refetch and streaming hydration. Worth revisiting if the human wants it.
